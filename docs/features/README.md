# Hot Ticket: документация функций

Эта папка описывает фактически реализованное поведение проекта Hot Ticket. Документация составлена по текущему коду, миграциям, systemd-конфигурации и CI/CD.

## Что представляет собой продукт

Hot Ticket — сервис поиска и отслеживания авиабилетов из городов Узбекистана. Он состоит из Telegram-бота, Telegram Mini App, административной панели и фоновой синхронизации с Aviasales Explore API. Все компоненты используют одну SQLite-базу.

Главная идея продукта:

> Не заставлять пользователя постоянно искать дешёвые билеты, а сообщать ему, когда подходящее предложение появится.

Текущие продуктовые ограничения:

- город вылета выбирается только среди поддерживаемых городов Узбекистана;
- валюта зафиксирована как узбекский сум (`UZS`);
- источник билетов — Aviasales Explore Hot Offers;
- Telegram-бот использует long polling, а не webhook;
- уведомления доставляются Telegram-ботом;
- Mini App и бот используют общие профили, настройки и подписки.

## Статус терминов

- **Билет** — конкретное предложение, полученное от Aviasales и сохранённое в `tickets`.
- **Маршрут** — комбинация `origin + destination + trip class`; в БД она представлена SHA-256-хэшем нормализованной строки, например `TAS|IST|economy`.
- **Подписка / отслеживание / alert** — набор условий, по которым бот отправляет уведомления.
- **Наблюдение цены** — почасовой снимок минимальной цены определённой комбинации маршрута и условий.
- **Deal Score** — оценка текущей цены относительно дневной истории маршрута.
- **Человеческий клик** — переход, user-agent которого не классифицирован как Telegram preview, crawler или bot.
