# Поиск и каталог билетов

## Источник каталога

Каталог формируется из активных записей таблицы `tickets`, которые были получены последним успешным sync из Aviasales Explore Hot Offers.

Текущая область поиска:

- origin: выбранный пользователем город Узбекистана;
- currency: `UZS`;
- дата вылета: не раньше сегодняшней даты в `Asia/Tashkent`;
- класс: из профиля пользователя;
- багаж: из профиля пользователя.

## Что хранится у билета

- внутренний ID и стабильный `external_key`;
- origin и destination;
- дата и время вылета;
- дата возврата или `null`;
- цена и валюта;
- код/название авиакомпании, если источник их предоставил;
- количество пересадок в форме `is_direct`;
- эконом или бизнес;
- наличие багажа;
- нормализованная ссылка Aviasales;
- исходная ссылка и исходный JSON;
- даты первого и последнего наблюдения;
- признак активности.

## Дедупликация билетов

`external_key` строится из существенных полей предложения: маршрута, даты, search code, валюты и класса. При повторном sync существующий билет обновляется, а не вставляется повторно.

Если билет отсутствует в новом полном ответе своего `origin/UZS`, он становится неактивным. Неактивные билеты остаются в БД для истории, но не показываются пользователям.

## Фильтры Telegram-бота

`TicketService` поддерживает:

- destination;
- минимальную/максимальную дату вылета;
- максимальную цену;
- только прямые;
- класс пользователя;
- требование багажа;
- offset.

Результат сортируется по цене по возрастанию. Бот запрашивает 11 записей: 10 показывает, а дополнительная запись определяет наличие следующей страницы.

## Фильтры Mini App

Hot Deals API поддерживает:

- направление или «куда угодно»;
- диапазон дат;
- максимальную цену;
- прямой рейс;
- багаж;
- сортировку;
- cursor pagination.

Текущий интерфейс Mini App предоставляет направление, максимальную цену, прямой рейс, багаж и сортировку. Диапазон дат уже поддержан API и используется формой создания отслеживания.

## Сортировки Mini App

| Значение | Поведение |
|---|---|
| `best` | По убыванию Deal Score, затем по цене |
| `cheapest` | По цене по возрастанию |
| `recent` | По времени добавления |
| `departing_soon` | По ближайшей дате вылета |

Для `best` сервис берёт расширенный пул до 500 кандидатов, рассчитывает Deal Score и только затем применяет страницу. Для остальных сортировок pagination выполняется на уровне SQL-запроса.

## Кэш направлений

После каждого sync формируются отдельные списки destination для комбинаций:

- economy / business;
- багаж не обязателен / обязателен;
- текущая дата вылета;
- выбранного origin и `UZS`.

Бот использует этот кэш для быстрого меню городов. Устаревшие записи с другой датой очищаются.

## Локальные и международные направления

Классификация выполняется по country code из локального справочника IATA:

- `UZ` — локальное направление;
- остальные страны — международное.

Если город отсутствует в справочнике, интерфейс использует его IATA-код.
